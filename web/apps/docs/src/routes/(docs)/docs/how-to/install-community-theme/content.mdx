A community theme is a packaged set of CSS variables and a few
optional layout overrides that the operator can apply on top of
the brand. The marketplace ships two community themes in the
current release; backend persistence of installed themes is in
progress.

<ScreenshotPlaceholder caption="Theme marketplace page with the install and activate buttons" />

## Step 1 — Open the marketplace

From the sidebar, choose **Admin → Theme marketplace**. The page
shows a grid of available themes — each card carries the theme
name, a thumbnail, a one-paragraph description, and the install
button.

## Step 2 — Install

Click **Install** on the theme you want. Plexor downloads the
theme package, validates the manifest, and stores the theme files
in the local theme library. The install is recorded in the audit
log with the theme id and the operator.

The validation checks:

- The theme manifest is well-formed YAML.
- The CSS bundle compiles without syntax errors.
- The bundle declares a `theme.id` matching the manifest's
  `id` field.

A theme that fails validation is not installed; the audit log
records the failure with the validator's error string.

## Step 3 — Activate

Click **Activate** on an installed theme. Plexor applies the
theme's CSS variables on top of the brand and reloads the page
with the new theme in effect.

<Callout type="info">

In the current release, theme activation is **per session**. The
activated theme persists across navigation but does not yet
persist across server restarts — that is what the
`theme-marketplace-backend` change is preparing. Until backend
persistence lands, an operator who restarts the host must
re-activate the theme on the next login.

</Callout>

## Step 4 — Deactivate

Open the marketplace, find the active theme, and click
**Deactivate**. Plexor removes the theme's CSS variables and
restores the brand-only styling.

## What the operator sees when something is wrong

| Symptom | Likely cause | Fix |
|---|---|---|
| Install fails silently | Manifest validator rejected the bundle | Check the audit log for the validator's error string. |
| Activate has no visible effect | Theme's variables collide with the brand | Open the brand page and reset the accent colour, then re-activate. |
| Theme persists across sessions | You restarted the host | Re-activate after restart. Backend persistence ships in the next minor release. |
| Two themes are both "Active" | Activation race during page reload | Refresh the page once. |

## What to do next

- **Customize the brand** to set the operator-visible name and
  logo on top of the active theme.
- **Theme the console** if you want a deeper style change — see the
  admin chapter's theming page.
