Each Plexor organisation can authenticate its users against an
external OIDC identity provider instead of the local
email-and-password scheme. When OIDC is enabled, the local scheme
stops accepting passwords for that organisation's users — they
sign in via the IdP, and Plexor consumes the ID token at login.

This page walks through wiring an IdP. The recipe uses Keycloak as
the running example; the configuration for Authentik, Azure AD,
Google Workspace, and others follows the same shape.

<Callout type="warning">

Once you enable OIDC for an organisation, users who do not exist in
the IdP cannot log in — even if they have a local password. Plexor
emails no warning when an existing local user can't authenticate.
Make sure at least one admin user has migrated to the IdP before
flipping the switch.

</Callout>

## Step 1 — Create the IdP application

In the IdP's admin UI, create a new OIDC client for Plexor. The
required fields:

- **Client type** — `confidential`. Plexor authenticates against
  the IdP with a client secret; it cannot use public clients.
- **Redirect URI** — `https://<your-plexor-host>/oidc/callback`,
  where `<your-plexor-host>` is the URL operators reach Plexor at.
- **Allowed flows** — `authorization_code` with `refresh_token`.
  Plexor consumes the ID token at login and uses the refresh token
  to keep the session alive.
- **Allowed scopes** — `openid`, `profile`, `email`. Plexor reads
  the user's email and display name from the claims; no other
  scopes are required.

The IdP returns a **client id**, a **client secret**, and the
**issuer URL** (typically your IdP's realm/tenant URL). Save
these; Plexor asks for them in step 2.

## Step 2 — Configure Plexor

In Plexor, open **Admin → Auth provider** for the organisation. The
form asks for:

- **Issuer URL** — the IdP's discovery-document root. Plexor
  fetches `<issuer>/.well-known/openid-configuration` to discover
  the token and userinfo endpoints.
- **Client id** — the value the IdP gave you.
- **Client secret** — encrypted at rest with the data-protection
  key. The secret value is not displayed back after the first
  save.
- **Email claim** — which claim carries the user's email. The
  default is `email`; some IdPs use `upn` or a custom claim.
- **Display-name claim** — which claim carries the user's display
  name. The default is `name`.

Click **Test connection**. Plexor fetches the discovery document,
authenticates against the token endpoint with your client
credentials, and reports the result. If the test fails, the most
common causes are:

- The client id or secret is wrong.
- The issuer URL does not resolve from the Plexor host.
- The IdP requires `client_credentials` for OIDC introspection and
  Plexor is sending something else.

Do not enable the provider for the organisation until the test
passes.

## Step 3 — Enable

Toggle the **Enable for this organisation** switch. Plexor starts
issuing 302 redirects to the IdP's authorization endpoint on
subsequent logins.

The first user to log in via the IdP becomes a regular Plexor user
with no role bindings. The platform admin assigns role bindings
exactly as for a local user.

<Callout type="warning">

The seed `*` super-admin role is **retained** even when OIDC is
enabled. The seed admin user — typically the slug you supplied at
install time — keeps the `*` wildcard regardless of which provider
is configured. This is the break-glass path: if the OIDC
configuration breaks, the seed admin can sign in locally and fix
the configuration. Do not delete the seed admin user.

</Callout>

## Step 4 — Audit

Open the organisation's audit log; the auth-provider switch is
recorded as `iam.org.auth.updated` with the actor's user id. The
test endpoint's results are kept at
`GET /api/v1/iam/orgs/{orgId}/auth-provider/test` for 24 hours;
after that they age out and the next call records a fresh event.

## What can go wrong

| Symptom | Likely cause | Fix |
|---|---|---|
| `Test connection` returns 401 | Wrong client secret | Reset the secret in the IdP and re-enter it in Plexor. |
| `Test connection` times out | Issuer URL not reachable from Plexor | Check DNS resolution from the host. |
| Users exist locally but cannot log in | OIDC is enabled and the email is not in the IdP | Add the user to the IdP, or disable OIDC. |
| Seed admin cannot log in | The local-account scheme is disabled because OIDC is on | Connect to the host's database and `UPDATE users SET auth_provider='local' WHERE email='<seed>'`. The seed admin returns. |

The last row is the break-glass path. It is intentionally
unsupported in the console UI because it bypasses the audit log;
do not ship a regular recipe that relies on it.
