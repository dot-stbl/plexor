The quotas subsystem caps countable resources at three nested scopes
(organisation, team, folder) and emits two signals (the 80% warning
and the 100% block). This page is the operator-facing reference
for the catalog, the walker, and the signals.

## Catalog

| Key | Counts | Default | Period |
|---|---|---|---|
| `compute.vms.count` | Number of VMs in the scope. | 100 | none |
| `compute.vms.vcpu` | Cumulative vCPU across VMs. | 256 | none |
| `compute.vms.ram_gb` | Cumulative RAM GiB across VMs. | 1024 | none |
| `compute.clusters.count` | Clusters in the org. | 10 | none |
| `compute.workloads.count` | Workloads across clusters in the org. | 100 | none |
| `storage.volumes.count` | Volumes in the scope. | 200 | none |
| `storage.volumes.gb` | Cumulative volume GiB. | 4096 | none |
| `network.floating_ips.count` | Floating IPs in the scope. | 10 | none |
| `network.load_balancers.count` | Load balancers in the scope. | 20 | none |
| `api.requests.per_hour.user` | Per-user request count, hourly window. | 1000 | hour |
| `api.requests.per_hour.org` | Per-org aggregate, hourly window. | 10000 | hour |

The catalog is **closed**. Operators cannot create new keys from
the console. Adding a key is a feature change that ships with a
release.

## Scope resolution walker

When a quota check happens, the walker resolves the effective
value as follows:

1. If a folder-scoped assignment exists for the key, the folder
   value wins.
2. Else, if a team-scoped assignment exists for the key, the
   team value wins.
3. Else, if an org-scoped assignment exists for the key, the org
   value wins.
4. Else, the catalog's default value wins.

The walker returns the **minimum** value found, scoped to the
narrowest match. A folder override of 10 trumps an org default of
100.

## The two signals

A quota check returns one of three results:

- **Allowed** — the request fits within the limit. No signal.
- **AllowedWithWarning(thresholdPct: 80)** — the request fits, but
  crosses 80% of the effective limit. The response carries the
  `X-Quota-Warning: true` header; the audit log carries
  `quotas.limit.approaching`.
- **Denied** — the request would exceed the effective limit. The
  handler throws `QuotaExceededException`; the API responds with
  HTTP 429 and `code = "quotas.exceeded"`.

There is no `AllowedWithOverride` or admin-bypass path. The way
past a Denied is to raise the assignment.

## Rate limits

Two of the catalog keys are **rate limits**, not resource caps.
They use a sliding-window count over the `rate_limit_events` table:

- `api.requests.per_hour.user` — per-user count, hourly window.
- `api.requests.per_hour.org` — per-org aggregate, hourly window.

A rate-limit check applies to **both** the principal (user id or
API key id) and the organisation. Plexor returns the more
restrictive of the two results.

The `rate_limit_events` table is bounded by a daily background
service that deletes events older than the longest retention
window (1 hour). The cleanup runs once per day and is itself
audited.

## Audit integration

Every quota operation emits an audit event:

| Action | When |
|---|---|
| `quotas.assignment.changed` | `PUT /api/v1/quotas/assignments` succeeded. |
| `quotas.assignment.removed` | `DELETE /api/v1/quotas/assignments/{id}` succeeded. |
| `quotas.usage.exceeded` | Quota walker returned Denied. |
| `quotas.limit.approaching` | Quota walker returned AllowedWithWarning. |

The four action names are stable. Clients can branch on them in
their SIEM rules without worrying about format drift.

## Endpoints

| Endpoint | Permission | Effect |
|---|---|---|
| `GET /api/v1/quotas/definitions` | `quotas.read` | List catalog keys. |
| `GET /api/v1/quotas/assignments?scope=…` | `quotas.read` | List assignments at the given scope. |
| `PUT /api/v1/quotas/assignments` | `quotas.assign.org` | Create or update an assignment. |
| `DELETE /api/v1/quotas/assignments/{id}` | `quotas.assign.org` | Remove an assignment. |
| `GET /api/v1/quotas/usage?scope=…` | `quotas.read` | Current usage at the given scope. |
| `GET /api/v1/quotas/effective?scope=…` | `quotas.read` | Resolved effective value per key. |

All endpoints are org-scoped — a user in Org X cannot see or
assign quotas for Org Y.
