Plexor ships two storage primitives that look different but solve
overlapping problems. **Volumes** are block devices you attach to a
workload; the workload sees them as raw disk. **Buckets** are
S3-compatible object stores; clients see them as keys and bytes over
HTTP. Picking between them is mostly about access pattern, not
capacity.

## Volumes — block storage

A volume is a raw block device provisioned inside Plexor's storage
backend (Ceph RBD by default, local-lvm in single-node installs).
You size it at creation (in gibibytes), attach it to one workload at
a time, and resize it online without stopping the workload.

The operator-facing fields:

- **Name** — unique per cluster, kebab-case slug.
- **Size** — gibibytes, between 1 GiB and the cluster's max (16 TiB
  on Ceph RBD, 1 TiB on local-lvm).
- **Folder** — the scope the volume lives in. Volumes are
  folder-scoped.
- **Attached workload** — null when the volume is detached, the
  workload id when attached.

When you attach a volume to a workload, the workload sees it as a
new raw device (typically `/dev/vdb` or `/dev/disk/by-id/...`).
Plexor does not format the device — the workload's guest OS is
responsible for partitioning, formatting, and mounting.

When you resize a volume, Plexor updates the backend's size and the
guest OS observes the new size at the next SCSI rescan. Online
expansion requires a guest that supports it (modern Linux does).
Shrinking is not supported — once a volume is bigger it stays
bigger.

## Buckets — S3-compatible object storage

A bucket is an S3-compatible object store. Clients speak the S3
HTTP API to it; Plexor (via Ceph RGW by default, MinIO in
single-node installs) handles the storage. A bucket is reachable
from any workload inside the same VPC, and from outside Plexor if
you expose it explicitly.

The operator-facing fields:

- **Name** — DNS-label rules: 3–63 lowercase characters, dashes
  allowed, no underscores, no uppercase. Plexor refuses to create a
  bucket whose name conflicts with one already registered in the
  DNS zone.
- **Region label** — a free-form label (`eu-central-1`,
  `home-lab-east`); Plexor does not enforce uniqueness across the
  region dimension, but clients typically include the label in their
  request signing.
- **Folder** — the scope the bucket lives in.
- **Default bucket policy** — private by default. Plexor does not
  ship a public bucket creation path; making a bucket publicly
  readable is an explicit policy edit that leaves an audit entry.

A bucket's data is durable across host failures (when backed by
Ceph RGW with replication) but is not versioned by default. To keep
historical versions, enable versioning on the bucket — that is a
per-bucket setting, not a cluster-wide default.

## Which to use, when

The decision tree is short:

- The workload needs a filesystem, a database, or anything that
  assumes a block device → **volume**.
- The workload produces files it wants to share with another
  workload, or with something outside Plexor → **bucket**.
- The data is large (terabytes), append-mostly, and read by
  separate consumers → **bucket**.
- The data needs random-access reads and writes at low latency →
  **volume**.

In practice, most Plexor deployments run a mix: a few volumes for
the database tier, and one or two buckets for shared assets,
backups, and inter-workload file exchange.

## What the operator sees when something is wrong

Three common failure modes:

1. **The workload cannot see the volume.** The volume is attached
   but the guest OS has not picked it up. On Linux, run
   `lsblk` to confirm the device is present, then `rescan-scsi-bus.sh`
   to force a rescan. If the device is still missing, check the
   workload's events in the audit log for an attach failure.
2. **A bucket returns 403 on a known-good credential.** The bucket's
   policy was edited to remove the role's read permission. Open the
   bucket's policy view and re-add the permission; Plexor logs the
   edit in the audit log.
3. **A bucket is full.** Plexor does not auto-evict — bucket
   storage is committed space. The operator decides what to delete
   or move out. A bucket at 80% of its quota gets the same warning
   signal every other quota uses; the warning appears in the bucket
   list view.
