Plexor is a self-hosted cloud platform for the operator who wants to
run virtual machines, private networks, block storage, and S3 buckets
on the servers already in their rack — and bolt on community apps
through a built-in catalog — without giving a hyperscaler the keys.

This documentation is written for the person who installed Plexor on
their hardware and now runs it day-to-day. It describes what the
system does for you, when to use which feature, and how to recover a
broken state. It does not describe how Plexor is built — for that,
see the project repository.

## What ships today

The current release runs a single `Plexor.Host` process on one host.
That process owns the control plane (organization, identity, audit)
and the data-plane state for everything that runs on it (compute,
networking, storage). A second process, the NodeAgent, joins the host
over a one-time token and runs workloads.

In production today you can:

- Create organisations, teams, and folders through the console.
- Authenticate locally with email and password, or wire an external
  OIDC provider per organisation.
- Provision virtual machines, Linux containers, and Kubernetes pods
  on one of three runtimes (`docker-compose`, `podman-quadlet`,
  `k3s`).
- Reserve floating IPs, create load balancers, attach block
  volumes, and create S3 buckets.
- Set per-organisation, per-team, and per-folder quotas on every
  countable resource.
- Issue API keys for service-to-service traffic — for example, the
  NodeAgent itself authenticates with an API key, not a session
  cookie.
- Inspect every state-changing call in the audit log.

## How to read this site

The documentation is split into six chapters that follow the
[Diátaxis](https://diataxis.fr) model: each page knows what kind of
page it is, and the four roles do not overlap.

- **Getting started** — tutorials. Read top to bottom on day one.
- **Concepts** — explanation. Read non-linearly, when you need a name
  for something.
- **How-to** — task recipes. Open the page, do the task, close the
  tab.
- **Admin** — operations and hardening. Read when something needs to
  keep working.
- **Reference** — exhaustive catalogs. Skim until you find the row.
- **FAQ / Troubleshooting** — symptom → cause → fix. Search for the
  thing that is on fire.

If you only have ten minutes, read **Concepts → Orgs, teams, and
folders**. The 3-tier scope hierarchy is the single most important
mental model in Plexor; everything else hangs off it.
