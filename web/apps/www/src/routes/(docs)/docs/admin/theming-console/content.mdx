The console's appearance is configurable per organisation. Two pages
in the admin sidebar cover it:

- **Admin → Branding** — the name, logo, accent colour, surface tint
  and a small custom-CSS escape hatch.
- **Admin → Theme marketplace** — pick a community theme from the
  built-in library and apply it on top of the brand.

Themes are a cosmetic preference — what the console looks like to the
operator — not a feature of the platform. The eight product surfaces
are compute, networking, storage, identity, marketplace, quotas,
audit, and console theming. Themes is the last of the eight.

## Branding

Open **Admin → Branding**. The page has two columns: the form on the
left, the live preview on the right. Every form edit is reflected in
the preview within ~200 ms; no need to save and reload.

| Field | Effect |
|---|---|
| Brand name | Top-of-page wordmark. Up to 32 characters. |
| Logo image | Replaces the wordmark icon. PNG, JPG, or SVG. Max 256 KiB. |
| Accent colour | Primary surface tint. Hex (`#0066ff`) or `oklch()` value. |
| Surface tint | Secondary surface for headers and cards. |
| Custom CSS | An escape hatch for anything the form does not cover. Max 16 KiB. |

The accent colour drives the focus ring, the link colour, and the
primary button. The surface tint drives the page header and the card
backgrounds. The two are coordinated — picking an accent and a surface
from the same hue keeps the chrome coherent.

<Callout type="warning">

The custom-CSS field is parsed and applied inside a sandboxed
`<style>` element. It cannot introduce JavaScript, cannot reach
outside the console's CSS scope, and cannot inject external
resources (`@import` of remote URLs is rejected). The 16 KiB cap
prevents accidental megabytes of CSS.

</Callout>

Click **Save**. The new brand takes effect for the current
organisation immediately. There is no staging environment in the
current release; the preview is the staging environment.

If you want to roll the brand out across the operator-visible
console but keep your changes draftable, save the form values to a
local file before clicking **Save**. Restore them by pasting back
into the same fields.

## Theme marketplace

Open **Admin → Theme marketplace**. The page shows a grid of
available themes — each card carries the theme name, a thumbnail, a
one-paragraph description, and the install button. The marketplace
ships two community themes in the current release.

Click **Install** on the theme you want. Plexor downloads the theme
package, validates the manifest, and stores the theme files in the
local theme library. The install is recorded in the audit log with
the theme id and the operator.

The validation checks:

- The theme manifest is well-formed YAML.
- The CSS bundle compiles without syntax errors.
- The bundle declares a `theme.id` matching the manifest's `id`
  field.

A theme that fails validation is not installed; the audit log records
the failure with the validator's error string.

Click **Activate** on an installed theme. Plexor applies the theme's
CSS variables on top of the brand and reloads the page with the new
theme in effect.

<Callout type="info">

In the current release, theme activation is **per session**. The
activated theme persists across navigation but does not yet persist
across server restarts — that is what the `theme-marketplace-backend`
change is preparing. Until backend persistence lands, an operator who
restarts the host must re-activate the theme on the next login.

</Callout>

Open the marketplace, find the active theme, and click
**Deactivate**. Plexor removes the theme's CSS variables and restores
the brand-only styling.

## What the operator sees when something is wrong

| Symptom | Likely cause | Fix |
|---|---|---|
| Logo does not appear | File exceeds 256 KiB or wrong content type | Resize or re-export the image. |
| Accent colour is invisible on buttons | Accent and surface tint are too close in luminance | Pick a higher-contrast tint. |
| Custom CSS does not apply | Selector does not match the rendered DOM, or syntax error | Open the browser's element inspector and check whether your selector matches. Plexor refuses to save CSS with a syntax error. |
| Other organisations see your changes | Branding is org-scoped; this means your scope switcher was on the wrong org | Switch to the right org and check whether the brand is set there too. |
| Edit the brand fields, click Save, reload — the brand is back to the old values | Two operators are editing the brand concurrently | Coordinate brand edits in chat — there is no field-level lock in the current release. |
| Install fails silently | Manifest validator rejected the bundle | Check the audit log for the validator's error string. |
| Activate has no visible effect | Theme's variables collide with the brand | Open the brand page and reset the accent colour, then re-activate. |
| Theme persists across sessions | You restarted the host | Re-activate after restart. Backend persistence ships in the next minor release. |
| Two themes are both "Active" | Activation race during page reload | Refresh the page once. |

The audit log records every branding change and every theme
installation. Branding entries record the operator, the timestamp,
and the changed fields (not the values — the brand is not
security-sensitive); theme entries record the theme id and the
operator.
