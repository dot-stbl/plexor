A glossary of every term the Plexor console and the
documentation use. One paragraph per term, with a pointer to the
concept page that goes deeper when there is one.

## A

**Audit entry** — a row in the audit log that records a single
state-changing operation. Carries the actor, the action (a stable
dot.case wire name), the target, the payload, and the timestamp.
See **Concepts → Audit log**.

**Audit log** — the chronological feed of every state-changing
operation Plexor performed. Queryable by action prefix, target,
and time range. The default retention window is 90 days.
See **Concepts → Audit log** and **Admin → Reading the audit log**.

**Auth provider** — the per-organisation identity scheme. Either
the local email-and-password scheme or an external OIDC provider.
Switching the scheme is admin-only and audit-logged.
See **How-to → Configure OIDC**.

## B

**Bearer token** — the credential format used to authenticate
against the REST API. Two shapes: a JWT for user sessions (issued
by the console login flow) and `kid_<key_id>.<secret>` for API
keys (issued via the API keys page).

**Bucket** — an S3-compatible object store inside Plexor's
storage backend. Accessible by S3 clients with a Plexor-issued
access key and secret.
See **Concepts → Storage**.

**Bcrypt** — the password-hashing function Plexor uses for local
users. Cost factor 12 (~250 ms on a modern CPU).

## C

**Cluster** — one Plexor.Host control plane plus the zero or more
Plexor.NodeAgent data-plane agents that have joined it. A
self-hosted install has exactly one cluster.

**Console** — the operator-facing web UI for Plexor. Lives at
`<your-plexor-host>/`. Uses the same data as the REST API but
renders it for direct manipulation.

**Control plane** — the part of Plexor that decides what to run,
where, and with what resources. Hosted by Plexor.Host.

**Custom role** — a role an admin creates with an explicit list of
permissions. Built-in roles are immutable; custom roles are not.

## D

**Data plane** — the part of Plexor that actually runs workloads.
Hosted by Plexor.NodeAgent processes that joined the cluster.

**Disk image** — the template used by a VM workload's root disk.
Lives in the cluster's image library; the agent provisions a
libvirt volume from the image when the workload boots.

## E

**Effective value** — the result of the quota scope-resolution
walker for a given `(scope, key)` request. Returns the minimum
value found across the three scopes (folder, team, org), or the
catalog default if no assignment exists.

**EffectiveFrom / EffectiveUntil** — the date range a quota
definition or assignment is in force. Null on either side means
"open-ended in that direction".

## F

**Failed-login counter** — per-user counter of consecutive failed
logins. Drives the 5/10/15 lockout schedule.
See **Admin → Lockout recovery**.

**Floating IP** — a public IP address that can be reserved and
reassigned between workloads. Used for inbound traffic and for
workload migration without DNS propagation delay.
See **Concepts → Networking**.

**Folder** — the third tier of the org hierarchy and the default
place for resources. Multiple folders per team are typical.

**Fresh token** — an API key or session that has not been used
yet. Can be revoked cleanly; no audit entries reference it.

## J

**JWT** — a JSON Web Token. Plexor's access tokens are
ES256-signed, 15-minute-lifetime JWTs. The payload carries `sub`,
`tid`, `iss`, `aud`, `jti`, `iat`, `nbf`, `exp`, `service`,
`roles[]`, and `permissions[]`.

**Join token** — a one-time token used by a Plexor.NodeAgent to
join the cluster. Single-use, with a 7-day TTL.

## L

**Lifetime** — the maximum age a credential (refresh token, API
key, etc.) is valid for. Refresh tokens have a 7-day lifetime;
JWTs have a 15-minute lifetime; API keys have no lifetime unless
an explicit `expiresAt` is set.

**Load balancer** — distributes inbound traffic across multiple
workloads. Two algorithms: round-robin and least-connections.
See **Concepts → Networking**.

**Lockout** — the temporary state a user account enters after a
sequence of failed logins. See the threshold schedule in
**Admin → Lockout recovery**.

## M

**MDX** — the Markdown variant Plexor's docs use. Allows
React components inside Markdown files.

## N

**Node** — a Plexor.NodeAgent that has joined the cluster. Each
node reports its hardware snapshot at first heartbeat, sends
heartbeats every 30 seconds, and runs workloads the control plane
assigns to it.

## O

**OIDC** — OpenID Connect. The external identity standard Plexor
supports for per-organisation authentication.
See **How-to → Configure OIDC**.

**Organisation** — the top of the resource scope hierarchy. Every
Plexor deployment has exactly one in the current release.

## P

**Pending** — the initial state of a workload, before a node
agent has accepted the work. Becomes `Provisioning` on Start.

**Permission** — a flat string of the form
`<service>.<resource>.<action>[.<qualifier>]`. The unit of RBAC in
Plexor. The catalog is the operator-facing list.
See **Reference → Permissions catalog**.

**Provisioning** — the state of a workload while a node agent
allocates resources on the runtime. The next state is `Running`
or `Failed`.

## Q

**Quota assignment** — a row in the quotas table that binds a
catalog key to a scope with a value. The walker's three-scope
lookup finds the effective value.

**Quota definition** — a row in the catalog that names a
countable thing Plexor caps. Closed set; ships with the platform.

## R

**Refresh token** — opaque token issued alongside a JWT, used to
obtain a new JWT without re-authenticating. Single-use with
family revocation.

**Role** — a named collection of permissions. A user's effective
permissions are the union of every bound role's permissions.

**Role binding** — a row that attaches a user to a role at a
scope. `UNIQUE (user_id, role_id, team_id, folder_id)`.

**Runtime** — the workload substrate Plexor uses to run workloads.
Three ship in the current release: `docker-compose`,
`podman-quadlet`, `k3s`. Immutable after cluster creation.

## S

**Scope** — the combination of organisation, team, and folder
that a request operates on. The scope switcher in the console
header is the operator-facing control for it.

**Scope switcher** — the header dropdown that picks the active
organisation, team, and folder. Re-points every page at once.

**Service account** — a Plexor user that authenticates with an API
key rather than a session cookie. Used by NodeAgent and by
operator scripts.

**Sigil** — the schema name for Plexor's identity module. The
operator-facing term is "Identity" or "Access". (Operators do not
need to use the schema name; this entry is here because the term
appears in some lower-level traces.)

**SNMP** — not implemented. Listed because some operator dashboards
expect it. Use the Prometheus exporter instead.

**SshKey** — a stored SSH public key for a user. Workloads that
accept SSH auth match against the user's key list.

**State machine** — the set of valid transitions between
workload lifecycle states. Rejects any transition not on the
graph; `compute.workload.invalid_transition` is the error code.

**Stopped** — the state of a workload after operator Stop. Disk
and configuration are preserved; can be restarted.

## T

**Team** — the second tier of the org hierarchy. A group of
people who share access to a slice of the deployment.

**Theme** — a packaged set of CSS variables that the operator can
apply on top of the brand. Two ship in the current release;
backend persistence is forthcoming.

**Token family** — the set of refresh tokens issued from one
login. Family revocation revokes every token in the family when
reuse is detected.

## U

**UUID v7** — the time-sortable UUID variant Plexor uses for every
entity id. Generated at the application layer (never from the
database's SERIAL or IDENTITY).

## V

**Volume** — a block device provisioned from Plexor's storage
backend. Attach to one workload at a time; resize online.

**VPC** — a Layer 2 broadcast domain inside the host.
Workloads attached to a VPC can talk to each other; workloads in
different VPCs cannot, unless peered.

## W

**Workload** — anything Plexor runs on your behalf. Kinds: `vm`,
`lxc`, `k8s.pod`, `container`.

## X

**X-Quota-Warning** — the response header carried on every request
that succeeded but crossed the 80% quota threshold.
See **Concepts → Quotas**.
