# `@plexor/www`

The Plexor project website: marketing landing at `/`, operator docs at
`/docs/*`, and a versioned release changelog at `/changelog` — like
nextjs.org. Vite SPA — `web/apps/www/dist/` is the static build.

> **Agent-facing project rules live in [`AGENTS.md`](./AGENTS.md)** —
> read it before touching code. This README is operator-facing: how to
> run, build, deploy, and what to expect.

## Quickstart

```bash
# from repo root
cd web
bun install
bun run dev:www        # http://localhost:17101
```

Verify (no dev server):

```bash
bun run build:www      # static output → web/apps/www/dist/
bun run typecheck:www  # tsc --noEmit
bun run lint:www       # eslint --max-warnings 0
bun run test:www       # vitest run
bun run gate           # typecheck + lint + test
```

Visual check loop (renders each route headlessly, screenshots it, and
flags console warnings/errors, horizontal scroll, clipped text and
unlabeled icon buttons — no standing dev server required):

```bash
cd web/apps/www
bun run shot routes                                  # list every route
bun run shot page / /docs/getting-started /changelog \
  --theme both --mobile --full                       # screenshot + report
```

## Build output

`web/apps/www/dist/` after `bun run build:www`:

| Path | What |
|---|---|
| `dist/index.html` | SPA shell — every URL falls back to this on the server |
| `dist/assets/*.js` | Bundled JavaScript (one or more hashed chunks) |
| `dist/assets/*.css` | Bundled CSS, incl. Plexor DS tokens |
| `dist/assets/*.map` | Source maps (`vite.config.ts` → `sourcemap: true`) |

There are **no per-page HTML files** — TanStack Router renders
client-side, not SSG. Search engines see the shell only.

## Adding a new page (recipe)

```bash
mkdir -p src/routes/\(docs\)/docs/<chapter>/<slug>/
# create index.tsx + content.mdx mirroring the FAQ pattern at
# src/routes/(docs)/docs/faq/troubleshooting/index.tsx
# register the slug in src/components/docs/docs-sidebar.tsx (CHAPTERS array)
bun run build:www        # regenerates src/routeTree.gen.ts
```

## Theming

Three presets in `web/packages/ui/src/themes/presets.ts`:
`plexor-default-light`, `plexor-default-dark`, `plexor-noir`.
Operators pick one from the `<ThemeToggle />` dropdown in the header
(`components/chrome/theme-toggle.tsx`) — a checkmark marks the active
preset, no more blind cycling. Choice persists to `localStorage` under
`plexor-theme`. Inline boot script in `index.html` applies the chosen
theme before React mounts — no FOUC. Full contract:
[`AGENTS.md`](./AGENTS.md) §6.

## Deployment

`bun run build:www` produces `web/apps/www/dist/`. **No Dockerfile,
nginx config, or CI deploy step is set up yet.** When the operator is
ready to host:

1. `bun run build:www` → `web/apps/www/dist/`.
2. Serve `dist/` from any static host (nginx, Caddy, S3 + CloudFront).
3. Configure SPA fallback: every URL → `/index.html` (TanStack Router
   SPA, not per-page SSG).
4. Reserve an origin (e.g. `plexor.stbl.space`) — dev runs on
   **:17101**, prod on **443/80**.
5. Cache headers:
   - `/assets/*` → `Cache-Control: public, max-age=31536000, immutable`
     (filenames are content-hashed).
   - `/index.html` → `Cache-Control: no-cache` (always revalidate).

## Known limitations (v1)

- **No SSG per-page** — it's a Vite SPA. SEO crawlers see the shell.
  For SEO, add `vite-plugin-prerender-spa` or run a headless renderer
  in CI.
- **No analytics, cookie banner, or consent flow** — out of scope.
- **No per-page 404/redirect at the server level** — the SPA returns
  the same `index.html` for any URL; the client router renders
  `DocsNotFound` via `defaultNotFoundComponent`.
- **No automated deploy step** — operator deploys manually until CI
  deploy lands. The build-and-verify pipeline lands in
  `.github/workflows/www-build.yml`; deploy is the operator's call.
